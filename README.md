# RobinhoodTrader

An autonomous, single-user trading agent that uses [Claude](https://anthropic.com) as its decision-making brain, connected to Robinhood via their official MCP server. Comes with a clean web dashboard, configurable guardrails, approval gates, and portfolio mirrors — all running on your own infrastructure.

> **This is a personal tool.** Your API keys and credentials never leave your machine (or your own cloud deployment). There is no shared backend, no telemetry, and no third-party service beyond the APIs you configure yourself.

---

## What it does

- Claude (`claude-sonnet-4-6`) runs on a configurable schedule and reviews your Robinhood agentic portfolio, watchlist, and market conditions
- It can buy and sell through Robinhood's MCP server, subject to your guardrail rules
- You control every safety knob from a web UI: position size limits, daily loss halts, asset class toggles, and human approval gates for large or sensitive trades
- Approval requests are sent to you via SMS (Twilio) or email and show up on the dashboard — you approve or reject with one click
- It tracks congressional disclosures (Capitol Trades) and institutional 13F filings (SEC EDGAR) and can mirror trades from public figures at a configurable portfolio percentage
- Daily or weekly plain-English summaries are generated by Claude and delivered to your inbox or phone

## Architecture

```
┌─────────────────────────────────────────────────────┐
│                    Your browser                     │
│          FastAPI + Jinja2 dashboard (port 8000)     │
└────────────────────┬────────────────────────────────┘
                     │  REST API
┌────────────────────▼────────────────────────────────┐
│                  FastAPI app                        │
│  ┌────────────┐  ┌──────────────┐  ┌─────────────┐ │
│  │ APScheduler│  │ Agent loop   │  │ API routes  │ │
│  │ (15 min)   │→ │ (Claude SDK) │  │ (CRUD + UI) │ │
│  └────────────┘  └──────┬───────┘  └─────────────┘ │
│                         │                           │
│              ┌──────────▼──────────┐                │
│              │   Guardrail layer   │                │
│              └──────────┬──────────┘                │
└─────────────────────────┼───────────────────────────┘
                          │ MCP
          ┌───────────────▼───────────────┐
          │   Robinhood Agentic Account   │
          │  (isolated from main account) │
          └───────────────────────────────┘

PostgreSQL ──── stores trades, watchlist, alerts, config
Twilio / SMTP ─ approval requests and reports
Capitol Trades / SEC EDGAR ─ mirror sources
```

The Robinhood agentic account is **completely isolated** from your main Robinhood brokerage account. Only funds you explicitly deposit into the agentic account are accessible to this agent.

## Security model

| Concern | How it is handled |
|---|---|
| API keys | Stored only in your local `.env` file, never committed (`.gitignore` enforced) |
| Robinhood access | Uses Robinhood's official MCP server with your own credentials — no third-party proxy |
| Account isolation | Robinhood agentic account is separate from your main portfolio by design |
| Trade approval | Human-in-the-loop gates for new positions, full exits, and large trades |
| Guardrails | Position size cap, daily trade limit, daily loss halt — all configurable, all enforced before any order reaches Robinhood |
| Deployment | Runs on your own machine or your own Railway project — no shared infrastructure |

**This project is designed for a single user.** Do not expose the dashboard to the public internet without adding authentication middleware.

## Running locally

### 1. Clone and set up the environment

```bash
git clone https://github.com/m-np/RobinhoodTrader.git
cd RobinhoodTrader

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

### 2. Configure your secrets

```bash
cp .env.example .env
```

Open `.env` and fill in your values:

```env
# Required
ANTHROPIC_API_KEY=sk-ant-...
ROBINHOOD_MCP_URL=https://agent.robinhood.com/mcp/trading
DATABASE_URL=postgresql://localhost/robinhoodtrader

# Optional — SMS alerts via Twilio
TWILIO_ACCOUNT_SID=AC...
TWILIO_AUTH_TOKEN=...
TWILIO_FROM_NUMBER=+1...
NOTIFY_TO_NUMBER=+1...

# Optional — email reports
NOTIFY_EMAIL=you@example.com
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=you@gmail.com
SMTP_PASSWORD=...        # use a Gmail App Password, not your main password
```

The `.env` file is listed in `.gitignore` and will never be committed.

### 3. Create the database

```bash
createdb robinhoodtrader
```

The app runs Alembic migrations automatically on startup, so no manual `alembic upgrade` is needed.

### 4. Start the app

```bash
python main.py
```

On first boot you will see:

```
INFO  Running database migrations...
INFO  Migrations complete
INFO  Seeding default config knobs
INFO  Scheduler started: agent every 15 min, waves every 5 min
INFO  Uvicorn running on http://0.0.0.0:8000
```

Open **http://localhost:8000** in your browser.

### 5. What to expect on first run

1. The dashboard loads with empty portfolio and no signals — this is expected until the agent's first cycle runs.
2. If your Robinhood agentic wallet balance is $0, a yellow banner appears at the top and the agent skips trading until you fund the account.
3. The first agent cycle fires ~15 minutes after startup (configurable via `AGENT_INTERVAL_MINUTES` in `.env`). Claude will review your portfolio and watchlist and decide whether any trades are warranted.
4. All trades above $500 (configurable in Settings → Approval threshold) will appear as approval requests on the dashboard and trigger a notification before any order is placed.
5. Approval requests time out after 10 minutes by default and are automatically cancelled if you do not respond.

## Deploying to Railway

Railway is the easiest hosted option — it provides managed PostgreSQL and a public URL.

1. [Create a Railway account](https://railway.app) and install the CLI: `npm i -g @railway/cli`
2. From the project root:

```bash
railway login
railway init          # create a new project
railway add           # add a PostgreSQL plugin
railway up            # deploy
```

3. Set your environment variables in the Railway dashboard (same keys as your `.env`).
4. Set `DEPLOYMENT_MODE=railway` — this disables hot-reload and uses the `PORT` Railway assigns automatically.
5. Railway uses the `Procfile` to start the app: `web: python main.py`

The app will be available at your Railway public URL. Consider adding an auth layer (e.g. HTTP Basic Auth via an nginx proxy, or a simple middleware) before sharing the URL.

## Customising the agent's behaviour

All agent behaviour is controlled through the **Settings** page without touching code:

| Knob | What it controls |
|---|---|
| Asset class toggles | Which instrument types Claude is allowed to trade |
| Approval threshold | Dollar value above which every trade needs your sign-off |
| Gate: new positions | Require approval before opening any stock Claude doesn't already hold |
| Gate: full exits | Require approval before selling an entire position |
| Max position size | Hard cap on how much of the portfolio can be in one ticker (%) |
| Max trades per day | Hard stop after N executed orders |
| Daily loss halt | Suspend all trading if the portfolio is down more than X% for the day |
| Report frequency | Daily, weekly, both, or off — delivered at 4 PM ET after market close |

## Project structure

```
RobinhoodTrader/
  main.py              entry point — migrations, seeding, FastAPI + scheduler startup
  config.py            pydantic Settings, loaded from .env
  requirements.txt
  Procfile             for Railway / Heroku

  agent/
    loop.py            Claude agent cycle (tool-use loop)
    guardrails.py      all pre-trade rule checks + approval gate
    mcp_client.py      Robinhood MCP wrapper
    wallet.py          agentic wallet balance check
    scheduler.py       APScheduler jobs

  api/
    routes.py          all FastAPI endpoints
    deps.py            shared DB session dependency

  db/
    models.py          SQLAlchemy ORM (7 tables)
    session.py         engine + SessionLocal
    migrations/        Alembic env + initial migration

  ui/
    templates/         Jinja2 HTML (base, dashboard, watchlist, mirrors, settings)
    static/            style.css + app.js

  notifications/
    notifier.py        Twilio SMS + smtplib email

  mirrors/
    capitol_trades.py  congressional disclosure polling
    sec_edgar.py       13F institutional filing polling

  reports/
    generator.py       Claude-generated daily/weekly summaries

  alerts/
    market_waves.py    price move detection (≥3% triggers an alert)
```
